01문제 — 기록이 인바운드에서 시작된다

요청 문서가 요구하는 것은 "리드 발생부터 재계약까지"의 추적이다. 그런데 현행 CRM의 최초 기록점은 상담사의 인바운드 등록이다. 그보다 앞에 있는 영업 활동(발굴 컨택, 교육 참석)은 시스템 밖에서 일어나고, 메모로 적지 않는 한 소실된다. 결과적으로 계약이 성사돼도 그것이 영업이 만든 계약인지 순수 인바운드인지 구분할 수 없다.

현행개선 1차
최초 기록점인바운드 등록 (상담사)영업이력 등록 (영업팀) — 등록 즉시 기회 생성
영업 활동시스템 밖 · 개인 메모기회 단위로 CRM에 존재, 코드 자동 채번
인바운드↔영업 연결불가 (수기 메모 의존)연락처 자동 인식 + 영업이력 검색 모달
계약↔영업 연결없음계약관리 화면에 영업담당자·기회코드 매핑
성과 조회불가기회 → 인바운드 → 계약 전환 퍼널 (경영·영업 리드)

02프로세스 스윔레인

5개 레인 × 4개 국면. 붉은 테두리가 신규, 회색이 현행 유지다. 핵심은 국면 2의 분기 — 상담사는 아무것도 외우지 않고, 시스템이 연락처로 먼저 판정한 뒤 못 찾을 때만 검색 모달을 연다.

영업팀 교육 상담사 계약 담당 시스템(자동) ▬ 붉은 테두리 = 신규 ▬ 회색 = 현행 유지

03분기 정의 — 인바운드 매칭

분기조건화면 동작상담사가 하는 일
A연락처가 소장DB·교육DB·진행중 기회 중 하나와 일치인바운드 슬라이더 상단에 매칭 배지 자동 노출. 클릭 시 단지·담당·이전 이력이 폼에 채워짐배지 확인 후 클릭 1회

051차 범위 / O3 이관 경계

이 선을 긋지 않으면 "왜 접점 히스토리가 없느냐"가 바로 돌아온다. 요청 문서의 요구 전체를 부정하는 게 아니라, 현행 화면으로 즉시 얻을 수 있는 것부터 얻고 나머지는 CRM 개편(O3)에서 흡수한다는 순서 선언이다.

1차 (이번)O3 이관 (CRM 개편, 9~12월)
영업이력 등록 + 기회 자동 생성단지정보 탭 상태 스트립 고도화 (고객상태 판정 규칙 적용)
인바운드 매칭 A·B·C 분기접점 히스토리 전면 누적 (모든 접점 시간순 타임라인)
계약관리 필드 2개 추가운영·적산 연결 (문의유형·처리일·지연 추적)
교육 DB 업로드·연락처 매칭출처별 성과 대시보드 고도화 · 리텐션 지표
기회→계약 전환 퍼널 기본 뷰할인 승인 워크플로우 · 데이터 등급(마스킹) 전면 적용

06확정 · 미확정

확정

가등록 단지영업 화면에서도 단지 신규 등록 가능. 등록된 단지는 상담 화면에서 수정 가능 — 양방향 모두 개방. 수정 이력만 남긴다
교육 DB 유입 방식Google 스프레드시트 기반으로 전환. 교육 신청이 자사 도메인 경유로 변경되어 신청 데이터가 자사 서버에 저장됨 — 연락처 자동 매칭(A분기)의 기반이 서버 데이터로 확보. 참석자 엑셀 업로드는 과거분 백필 용도로 격하
단지 마스터 별도 탭만들지 않는다. 단지코드·지역·세대수는 현행 단지정보 탭에 이미 존재하고, 고객상태·최근 계약상태·최근 문의일은 입력값이 아니라 계약·접점 데이터의 계산값이다. 기존 단지정보 탭 상단에 자동 계산 상태 스트립을 추가하고, "단지 마스터"는 화면이 아닌 데이터 계층 명칭으로만 유지

미확정 — 개발·경영 협의 필요
